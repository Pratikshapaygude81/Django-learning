# Django Templates
## Reference:-https://www.w3schools.com/django/django_templates.php
## 1. Introduction

A Django template is used to generate HTML dynamically.

A template contains:
- Static HTML content.
- Dynamic content that can be inserted using Django Template Language (DTL).
- Template tags and filters to control and format the output.

**Example:** In a hospital appointment system, the home page can display a welcome message, hospital details, and appointment information.

## 2. Why Do We Use Templates?

Without templates, we can return plain text or manually construct HTML using `HttpResponse()`.

Templates help us:
- Separate HTML presentation from Python business logic.
- Reuse HTML layouts.
- Display dynamic data from views.
- Create maintainable web pages.

## 3. Template Folder Structure

Django supports storing templates inside individual applications.

For the Hospital Appointment Management System, the recommended structure is:

```text
config/
    settings.py
    urls.py

appointments/
    migrations/
    templates/
        appointments/
            home.html
    views.py
    urls.py
    models.py

manage.py
```

**Why use the additional `appointments` folder inside `templates`?**

It helps organize templates by application and avoids naming conflicts when multiple apps contain templates with the same filename.

## 4. Template Configuration

Django uses the `TEMPLATES` setting in `settings.py` to configure template engines.

Important settings:

| Setting | Purpose |
|---|---|
| BACKEND | Specifies the template engine. |
| DIRS | Specifies additional directories where Django searches for templates. |
| APP_DIRS | Allows Django to search inside installed applications' `templates` folders. |
| OPTIONS | Contains additional template engine settings. |

The default configuration generated by Django includes:

```python
'APP_DIRS': True
```

This allows Django to find templates inside installed applications.

## 5. Rendering Templates

Django provides the `render()` shortcut function.

It combines:
- The current request.
- The template file.
- Optional context data.

It returns an `HttpResponse` containing the rendered HTML.

The general structure is:

```python
render(request, template_name, context=None)
```

| Argument | Meaning |
|---|---|
| request | The current HTTP request. |
| template_name | The name or path of the template. |
| context | Optional dictionary containing data for the template. |

## 6. Template Loading

Django provides `get_template()` through `django.template.loader`.

It loads a template and returns a Template object.

If Django cannot find the requested template, it raises `TemplateDoesNotExist`.

The template loading process depends on the template engine configuration and its loaders.

## 7. Context in Django

Context is data passed from a view to a template.

It is generally provided as a Python dictionary.

For example, a hospital home page may receive:

- Hospital name.
- Welcome message.
- Doctor information.
- Appointment details.

The template can display these values dynamically.

## 8. Django Template Language (DTL)

Django Template Language provides special syntax for displaying and controlling dynamic content.

It has four important constructs:

### A. Variables

Variables display values passed through the context.

Syntax:

```django
{{ variable_name }}
```

### B. Tags

Tags provide logic and control structures inside templates.

Syntax:

```django
{% tag_name %}
```

Common examples:
- `if` – Conditional statements.
- `for` – Loops.
- `csrf_token` – CSRF protection token in forms.
- `url` – Generates URLs using URL patterns.

### C. Filters

Filters modify or format variable values before displaying them.

Syntax:

```django
{{ variable_name|filter_name }}
```

Examples:
- `title` – Converts text into title case.
- `upper` – Converts text to uppercase.
- `lower` – Converts text to lowercase.
- `date` – Formats date values.

### D. Comments

Comments are not displayed in the rendered HTML.

Single-line comment syntax:

```django
{# This is a comment #}
```

## 9. Template Inheritance

Template inheritance allows multiple pages to share a common HTML layout.

For example, a hospital website may have:
- A common header.
- A navigation bar.
- A footer.
- Different page content.

Important template tags:

- `extends` – Inherits from another template.
- `block` – Defines sections that child templates can override.
- `include` – Includes another template inside the current template.

This reduces repeated HTML code.

## 10. Template Security

Django templates provide automatic HTML escaping by default.

This helps protect pages against certain cross-site scripting (XSS) attacks when displaying untrusted content.

Avoid disabling autoescaping for untrusted data.

## 11. Template Errors

| Error | Meaning |
|---|---|
| TemplateDoesNotExist | Django cannot find the requested template. |
| TemplateSyntaxError | The template contains invalid template syntax. |

Common reasons:
- Incorrect template filename.
- Incorrect folder structure.
- App missing from `INSTALLED_APPS`.
- Incorrect template path.
- Incorrect template syntax.
